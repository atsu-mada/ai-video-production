Generation Handoff

Prepare a reviewable handoff for a separate provider execution skill. Record the provider profile, model, execution skill, input references and their roles, duration, prompt artifact, output contract, validation commands, and approval state. Keep credentials, tokens, and private account data out of the handoff.

Use Markdown links for every local Input references: entry and for Prompt artifact:; an explicit HTTP or HTTPS URL is reserved for an external reference. The handoff may identify the next provider skill and its current contract, but authoring it does not submit a job. Recheck live provider capabilities at execution time and preserve the package's reference and duration constraints. The embedded Provider profile: controls duration validation; an optional --profile <name> must match it. Validate with <verified-cpython-3.14> scripts/validate_ai_video.py handoff <handoff> [--check-paths --project-root <project-root>] [--profile <name>].

Reference record

For every selected input, record its upload order, provider-visible tag, role, inherited attributes, excluded attributes, and content hash. Distinguish ordinary references from start or end frames. When no boundary frame is approved, keep those roles unset rather than relabeling a normal reference. Record scene, cut range, beat range, and job ID independently so provider limits never force a story-scene renumbering.

計画と実際の入力を分ける

保存済みプロンプトと、実際に入力されたプロンプト・参照の順序とタグ・開始/終了フレーム・設定・ジョブIDを別々に照合する。設定の記録は観測したsurfaceと日時に紐づけ、他の画面や現在の上限へ一般化しない。生成の準備と実行の承認は分け、Processingでの引継ぎを完成扱いにしない。
