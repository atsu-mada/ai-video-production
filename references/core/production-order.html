Production Package and Order

Scene-based Package Layout

Use this layout for a new scene-based package:

project/
├── 00_master-index.md
├── 00_common/
│   ├── 01_style-and-production-rules/
│   ├── 02_characters/
│   ├── 03_environments/
│   ├── 04_objects/
│   └── 05_prompt-library/
├── 01_scenes/
│   └── SC<NN>_<range>_<slug>/
│       ├── 00_scene-overview.md
│       ├── 01_used-common-assets.md
│       ├── 02_scene-assets/
│       ├── 03_storyboard/
│       ├── 04_text-storyboard/
│       ├── 05_cut-prompts/
│       ├── 06_scene-cut-manifest.csv
│       └── 07_generation-handoffs/
└── 99_manifests/
    ├── global-asset-manifest.md
    └── global-cut-manifest.csv

Placement test

  • Recurring and independently reusable: 00_common.
  • Appears only in one scene or one transient state: that scene's 02_scene-assets.
  • Prompt and rendered output stay adjacent.
  • Older drafts remain in place unless the user explicitly requests migration or deletion.

Order

  1. Lock style and timing.
  2. Inventory recurring assets.
  3. Create reference sheets.
  4. Create image-only storyboard.
  5. Create paired text storyboard.
  6. Write cut prompts.
  7. Get previz visual approval and a quoted estimate.
  8. Generate clips and edit only when separately requested.
  9. Build delivery variants and run delivery QA.

Approval gates

  • Previz visual approval — send the rendered previz (video or contact sheet) to the user and wait for an explicit visual OK before any paid generation that uses it.
  • Quote before paid steps — every paid step (generation, retake, extend, upscale) is preceded by a quoted estimate from the suite operator and the user's explicit OK. One approval covers one quoted step, not later ones.
  • A handoff marked approved for generation records the approval; it does not replace the quote.

Version bump rule

Every regenerated clip, edit, and export gets a new version suffix (_v<NN>). Never overwrite an accepted or delivered version; record which inputs each version was built from. See delivery variants.

Place recurring or independently reusable assets in 00_common/. Keep transient states and scene-only assets inside the owning scene. Keep each prompt beside its declared image or video output path. Leave existing drafts in place unless migration or deletion is explicitly requested.

Build in this order: style and timing, recurring assets, environment and object references, image-only storyboard, paired text storyboard, cut prompts, scene prompt, generation handoff, then provider execution when separately requested.
