採用版と編集引継ぎ

「最新のファイル」を自動採用しない。採用する制作パッケージのIDと改訂版を先に固定し、その版の scene → job → take → 実ファイルを辿れる一覧を作る。別の構成版の生成済みファイルを、同じシーン名という理由だけで混ぜない。

引継ぎの最小情報

  • 順序、scene_id、job_id、take_id、作品内相対パス、SHA-256、実尺。
  • 仮候補・採用・不採用、技術QC、知覚レビュー、承認の参照、配置理由。
  • 欠損ジョブ、未生成、生成中、未確認、不合格を区別した残件。
  • 重複配置や意図的な除外は理由を残す。除外により作品範囲が変わるときは、パッケージの改訂理由と承認を記録する。

未完の引継ぎは未確定値を null や pending として渡す。再開先に「完了したはず」を補完させず、最後に観測した状態、次の確認行為、再送してはいけない既存ジョブを明示する。

任意の editorial-selection.json

既存10制作モードの必須ファイルは増やさない。編集選択の機械検査が必要な場合だけ、draftテンプレートとschemaを使う。

<verified-cpython-3.14> scripts/validate_ai_video.py editorial-selection editorial-selection.json --project-root /project/root --check-paths

mode=draft は未確定を保持する。mode=final は採用状態、正の有限な尺、パスとハッシュ、技術QC合格、知覚レビュー合格、承認参照、欠損なしを要求する。同じjob/takeを再配置するときは placement_reason を付ける。

straight_cuts の overlap はすべて0。overlap 編集では先頭を0とし、各重なりを隣り合う両クリップの尺未満にする。合計は尺総和から重なりを引く。expected_total_secondsとの差は既定0.1秒以内（--timing-toleranceで明示変更）。

検証器が確認するのは記録の整合性。--check-pathsを付けたときだけ実在とハッシュを照合する。実際の再生、実尺の計測、視聴者の判断、人の承認を自動的に証明するものではない。

編集アプリでの確認

  1. 配置後、各クリップの順序と累積時間を一覧へ照合する。
  2. 編集アプリの保存完了を確認する。
  3. 書き出しファイルは別に存在・実尺・映像/音声・実時間再生を確認する。
  4. 提出・公開は明示された別操作と結果証拠で管理する。
